# Text-only export — пропуск медиа-постов без текста

Ветка: `del-images-form-posts`

## Проблема

Парсер экспортировал **все** сообщения канала, у которых есть либо текст, либо медиа. Для постов-картинок без подписи получались пустые «заглушки»:

```markdown
### [2026-06-18 00:46 UTC](https://t.me/liminalwriting/870)

> 📷 Photo
```

После `knife_posts.py` на каждый такой пост создавался отдельный файл (`001.md`, `002.md`, …) без полезного содержимого. То же касалось видео, документов и прочих медиа без caption.

Нужно было: **экспортировать только тексты**, изображения и медиа-заглушки не парсить.

## Решение

1. Сообщение без текста (и без Telegraph-статьи) **полностью пропускается**.
2. Строки вида `> 📷 Photo`, `> 🎥 Video`, `> 📎 …`, `> 🔗 …` **больше не пишутся**.
3. Если у поста есть и картинка, и подпись — сохраняется **только текст** (дата и ссылка).
4. Telegraph-статьи по-прежнему подтягиваются как полноценный текст.

## Поведение по типам сообщений

| Тип сообщения | Было | Стало |
|---|---|---|
| Только фото / видео / файл, без caption | Экспорт с `> 📷 Photo` и т.п. | Пропуск |
| Фото + текстовая подпись | Текст + `> 📷 Photo` | Только текст |
| Обычный текстовый пост | Текст | Без изменений |
| Ссылка на Telegraph | Полный текст статьи (или превью + stub) | Полный текст статьи, без media stub |
| Service-сообщения (join, pin, …) | Пропуск | Пропуск |

## Изменённые файлы

| Файл | Что сделано |
|---|---|
| `parser.py` | Основная логика: `resolve_post_text()`, фильтр пустых постов, удаление `media_type()` |
| `update_liminalwriting.py` | Та же логика для инкрементального апдейта liminalwriting |
| `update_twonovelists.py` | Та же логика для twonovelists |
| `README.md` | Описание формата вывода обновлено под text-only |

`knife_posts.py` не менялся: он режет уже готовый common-файл. Если в common нет медиа-заглушек, отдельные файлы под картинки тоже не появятся.

## Ключевая логика

Новая функция `resolve_post_text(msg)`:

1. Ищет Telegraph URL в тексте сообщения или в webpage-preview.
2. Если нашла и удалось скачать статью — возвращает полный текст.
3. Иначе возвращает `msg.text` (caption / обычный текст) или `""`.

В цикле экспорта:

```python
post_text = resolve_post_text(msg)
if not post_text:
    continue  # skip media-only
# пишем header + text, без media stubs
```

Счётчик **Total posts exported** теперь отражает число **реально записанных текстовых постов**, а не все сообщения, скачанные из Telegram.

## Что удалено

- Функция `media_type()` и запись блоков `> …` в Markdown.
- Импорты `MessageMediaPhoto`, `MessageMediaDocument` (и неиспользуемый `PeerChannel` в `parser.py`).
- Зависимость экспорта от наличия `msg.media` как достаточного условия для записи поста.

Остался только `MessageMediaWebPage` — чтобы достать URL для Telegraph.

## Миграция уже существующих выгрузок

Изменение влияет на **новые** прогоны парсера. Старые common-файлы и нарезанные `NNN.md` с `> 📷 Photo` сами не очищаются.

Чтобы привести канал в порядок:

1. Перепарсить канал (`parser.py` или `update_*.py`) — common-файл перезапишется без медиа-постов.
2. Перенарезать посты (`knife_posts.py` **без** `--incremental`, либо заново синхронизировать через `update_*.py`).

Важно: при полной перенарезке нумерация `001.md`, `002.md`, … сдвинется, если раньше в середину попадали image-only посты. Инкрементальный режим (`--incremental` / sync, который дописывает только в конец) **не удалит** уже существующие пустые файлы — их нужно убрать вручную или сделать полный resync.

## Проверка

После парсинга в выходном `.md` не должно быть строк:

- `> 📷 Photo`
- `> 🎥 Video`
- `> 🎵 Audio`
- `> 📎 …`

Посты вида «только картинка» не должны попадать ни в common-файл, ни в отдельные `NNN.md`.
